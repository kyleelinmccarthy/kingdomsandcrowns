# Kingdoms & Crowns

A Next.js (App Router) homeschool quest tracker with a three.js game, the Realm. Drizzle + libSQL (Turso in production, `local.db` in dev). Production is Vercel + Turso; the Cloudflare config is an unused option.

## Repo layout

Keep this layout. Put new files in the folder that already holds their kind, and update this section when you add a new kind of folder.

| Path | Holds |
|------|-------|
| `src/app/` | Routes only (App Router). `(app)` is the signed-in shell, `(auth)` and `(legal)` are route groups, `api/` the route handlers. Logic belongs in `src/lib/`, not in `page.tsx`. |
| `src/components/` | React components. Feature areas get a subfolder (`marketing/`, `realm/`, `realm3d/`); `ui/` is shadcn primitives. Tests sit next to the file they test (`foo.tsx`, `foo.test.tsx`). |
| `src/lib/` | Non-UI code: `actions/` (server actions), `services/`, `db/` (schema, migrations, seed and backfill scripts), `auth/`, `billing/`, `realm/` and `realm3d/` (game logic), `utils/`. |
| `src/content/` | Authored learning content (`drills/`, `sorts/` for the sorting locks, `review/`). |
| `src/hooks/`, `src/test/` | Shared hooks; shared test setup and helpers. |
| `public/` | Only files the site serves at a URL. Images for the marketing site go in `public/marketing/` (screenshots in `public/marketing/screens/`), with credits in `public/marketing/CREDITS.md`. Other served art: `public/cursors/`, `public/crown.svg`. |
| `assets/` | Source art that is not served (for example `assets/logos/`). Do not put it in `public/`. |
| `docs/` | All documentation; index in `docs/README.md`. See below. |
| `scripts/` | Operational scripts run with `node` or `npm run` (backups, password reset, env checks, screenshot capture). |
| `.superpowers/` | Agent working files: `realm-rules.md` (rules for Realm agents), `tools/` (screenshot tooling), `sdd/` (local ledgers and reports, gitignored), `shots/` (gitignored). |
| `.claude/worktrees/` | Git worktrees for parallel work. Remove a worktree and its branch once the branch is merged. |
| repo root | Only tool config that must live there (`package.json`, `next.config.ts`, `tsconfig.json`, `drizzle.config.ts`, `vitest.config.ts`, `eslint.config.mjs`, `wrangler.jsonc`, `vercel.json`, ...), `README.md`, `CLAUDE.md`, `AGENTS.md`. No loose images, docs or scratch files. |

### Docs

- `docs/deploy/`: how production runs and releases (`vercel.md`, `cloudflare.md`, `database-backups.md`).
- `docs/setup/`: one-time third-party setup (`oauth.md`, `stripe.md`).
- `docs/content/`: skill maps. `src/lib/utils/skills.test.ts` reads these by path, so don't rename or move them.
- `docs/superpowers/specs/`: design docs, named `YYYY-MM-DD-<topic>-design.md`.
- `docs/superpowers/plans/`: implementation plans, named `YYYY-MM-DD-<topic>.md`. A plan and its spec share the topic.
- Links between docs are relative. When you move a doc, fix links to it, including paths written in code comments (`grep -rn "<old-name>"`).

### Do not move

- `public/crown-email.png`: `src/lib/email-template.ts` links it by URL, and emails already sent still load it.
- `public/_headers`, `src/app/favicon.ico`: framework conventions that need those exact places.
- `scripts/backup-db.mjs` and `scripts/install-backup-timer.sh`: the installed systemd backup timer points at that path.
- `src/lib/db/migrations/` is generated by drizzle-kit; never hand-move or renumber files.

## Commands

```bash
npm run dev          # dev server
npm run lint && npm run typecheck && npm test
npm run db:generate  # after editing src/lib/db/schema.ts
npm run db:migrate   # apply migrations (local.db, or Turso when configured)
```

## Branches and worktrees

- `dev` is the working branch; `main` is what ships. Feature branches get merged into `dev`.
- After a branch is merged into `dev` or `main`, delete the branch and its worktree (`git worktree remove .claude/worktrees/<name>`, then `git branch -d <name>`). Leave unmerged branches alone.
- Several sessions can share one checkout: check `git branch --show-current` before committing, and stage only your own files.
